# TypeScript package

`@traxsharp/state-machine` is the TypeScript twin of `Trax.Effect.StateMachine`, published from `Trax.Api.StateMachine`.
Its exports are pinned by a committed baseline (`src/exports.test.ts`).

```bash
npm install @traxsharp/state-machine graphql-ws
```

`graphql-ws` is an optional peer dependency: a machine's push and the client `trax client` generates open their
socket with it. React is one too, for `@traxsharp/state-machine/react` and the generated hooks.

It is published to npm with every Trax release, at the same version as the NuGet packages: install the version
that matches your `Trax.*` packages. A twin generated by `trax machine generate` does not demand that version,
though: it records the [IR format](/docs/sdk-reference/statemachine-api/ir-format#the-formats-version) it was
generated for, and loads on any release of the package that reads that format, so a package upgraded without
regenerating keeps working until the format itself changes.

## Members

| Entry point | Holds |
| --- | --- |
| `@traxsharp/state-machine` | The engine, the typed view, the framework-free stores, the IR interpreter and the generators. Pure: no I/O. |
| `@traxsharp/state-machine/client` | Everything that talks to a Trax server: the typed executor over persisted documents, draft sessions, and the server-authoritative controller. |
| `@traxsharp/state-machine/react` | `useServerMachine` and `useRememberedMachine`. React is an optional peer dependency. |

### The engine and the typed view

| Export | What it is |
| --- | --- |
| `SnapshotMachine` | The reducer, the twin of the C# `SnapshotMachine`: `createInitialSnapshot`, `advance`, `applyOutcome`, `applyTimer`, `timer`, `rehydrate`, `serialize`, `canFire`, `availableTriggers`, `describe`. Every operation is total: `advance` answers with an `AdvanceResult`, `rehydrate` with a `RehydrationResult`. `rehydrate(json, { fromServer: true })` reads a snapshot the server sent: a custom rule the twin has no handler for counts as passed, since the server evaluated it, and the shape and every built-in rule are still checked. Any other read, and every `advance`, refuses such a rule. |
| `RefusalCode`, `ClientProblemCode` | `RefusalCode` holds every code a refusal carries, equal member for member to the C# enum ([result codes](/docs/sdk-reference/statemachine-api/result-codes)); some, such as `TOO_LARGE`, only a server answers. `ClientProblemCode` holds the codes the package reports itself: `GONE`, `NOT_READY`, `TRANSPORT_ERROR`, `NOTHING_TO_RETRY`, `DISPOSED`. A `problem.code` is one of the two. |
| `TypedMachine`, `typedMachineFromIr(ir, schemaHash?)` | The same engine with one machine's states, triggers and contexts as types (`MachineSpec`, `StateOf`, `TriggerOf`, `ContextOf`, `InputOf`). `typedMachineFromIr` builds one from an IR document; a generated twin calls it. A trigger whose edge runs an effect takes no input in a twin's types (the server's effect runner hands it the receipt), and `isEffectBound(trigger)` says which. |
| `machineFromIr(ir)` | Builds the untyped `MachineDefinition` an IR document describes, with its declarative guards, reducers, input schemas, outcomes and timers. |
| `MachineDefinition`, `TransitionDefinition`, `MachineTimer`, `Guard`, `Reduce`, `ContextValidator`, `InputValidator` | The definition `SnapshotMachine` runs. `InputValidator` is `(input) => string \| null`: the check of one trigger's input against its declared schema, null when it matches. `ContextValidator` is `(context, options?) => string \| null`, and `options.fromServer` is set on a snapshot the server sent. `Guard` is `(context, input, options?) => boolean`, and `options.inputUnknown` is set when the input is one only the server has: a guard built from the IR then counts every rule on the input, and every custom rule, as passing. |
| `IrDocument`, `IrTransition`, `IrOutcome`, `IrOutcomeEdge`, `IrTimer` | The [IR format](/docs/sdk-reference/statemachine-api/ir-format) as types. `IrTimer` is one state's timer: `state`, `trigger`, `target`, and either `after` or a context `field` with `min` and `max` (ISO-8601 durations). |
| `evaluateRule`, `applyReduction`, `validateSchema`, `validateInput` | The rule interpreter. `validateSchema(schema, context)` checks a context; `validateInput(schema, input)` checks a trigger's input as the C# engine does (no input reads as `{}`, anything but a plain object is refused). Both answer null when valid, else a message, and never throw. |
| `Rule`, `Reduction`, `ValueSource`, `SetStep`, `ContextSchema`, `FieldSchema`, `ValueSchema`, `RuleSource`, `JsonFieldType`, `CompareOp`, `CustomGuards`, `CustomReducers` | The [declarative data model](/docs/sdk-reference/statemachine-api/declarative-data-model). `ValueSchema` is the shape of one value (its `type`, `nullable`, an integer's `minimum` and `maximum`, a record's `fields`, a map's or list's `values`); `FieldSchema` adds the field's `name` and `constraints`. |
| `generateContextTypes`, `generateMachineFactory` | The generators that emit a twin from an IR. `trax machine generate` and the drift check call them. |
| `clientFormat`, `oldestClientFormatServed`, `requireClientFormat(n)` | The client format: the API code `trax client` generates calls. Generated code calls `requireClientFormat` with the format it was generated for when it loads, before any twin, and the runtime throws naming both formats and whether to upgrade the package or regenerate. |
| `enumerate`, `serializeCorpus` | Enumerate a machine into the differential corpus the C# engine replays. |

### Driving a machine in memory

From `@traxsharp/state-machine`, for a machine no server holds (a preview, a test, a form's own steps):

| Export | What it is |
| --- | --- |
| `MachineController` | A framework-free store held in memory: `send`, `can`, `available`, `reset`, `subscribe`, `getSnapshot`. It stores nothing, and a refused action still emits a view with its `problem`. A machine a server holds is driven through `ServerMachineController` instead. |
| `createFormView(machine, { steps, toContext })` | For a UI that owns its data and asks the machine: maps each UI step to a state (one to one), and gives `advance`, `can`, `snapshotFor`, `serialize`, `resume` and `isCommitted` in the UI's own step names. |
| `problemFromAdvance`, `problemFromRehydration`, `Problem` | A refusal shaped for display. |
| `createDevLogger` | Logs transitions and refusals in development. |

### Talking to a server

From `@traxsharp/state-machine/client` (`useServerMachine` from `@traxsharp/state-machine/react`):

| Export | What it is |
| --- | --- |
| `createMachineExecutor(endpoint, { machines, ... })` | The executor for machines the host exposes on the typed root. Each machine is given its `documents` (`MachineDocument`, from the [client manifest](/docs/sdk-reference/statemachine-api/client-manifest)), and every operation is sent by its persisted id; a machine with none throws when the executor is built. A client never sends a document of its own. |
| `createDraftSession({ executor, machine, id })`, `startDraft({ executor, machine, requestId, input? })` | One draft of one machine, every method total: a refusal is a `{ ok: false, code, message }`, an unreachable server is `TRANSPORT_ERROR` (`ClientProblemCode.TransportError`). `startDraft` creates a draft under an id the server mints. |
| `createMachineServer(endpoint, { machine, documents, socket, resubscribeDelays?, terminalStreamErrors? })` | One exposed machine's typed operations and its push stream (`<machine>Changed`), as the `MachineServer` a controller drives. `persistedMessageReplacer` is the graphql-ws `jsonMessageReplacer` it needs, and `DEFAULT_RESUBSCRIBE_DELAYS` (1, 2, then 5 seconds) the delays before a dropped stream is subscribed again. A socket error whose `code` is in `terminalStreamErrors` is not subscribed again: the stream delivers `{ type: 'ended', code, message }` and the controller stops with that code. A request rejected with such a code stops the controller the same way, through the server's `endedBy(error)`, instead of failing as a transport error that `retry` resends. The generated client passes `CONNECTION_CHANGED`. |
| `useRememberedMachine(machine, { server, rememberKey, ...})` | From `@traxsharp/state-machine/react`: `useServerMachine` over the instance this browser keeps in `localStorage` under `rememberKey`. It opens the remembered instance, or starts one under a requestId kept until the start answers, and adds `forget()`, which starts over. A `rememberKey` that changes opens that key's instance. An instance the stream says was deleted is forgotten and a new one started; one the server answers `NOT_FOUND` stops the hook (`error.deleted` false) and stays remembered, since the server answers another caller's instance the same way. Give each user a key of their own. The code `trax client` generates calls it as `useRemembered<Machine>()`, under `trax.<machine id>.<user>` for the `user` given to `configureTrax`. |
| `ServerMachineController` | The framework-free, server-authoritative store: the server applies every transition and the twin predicts. It reads every snapshot the server sends with `fromServer`, so a state that requires a custom rule opens without a handler in the twin. The twin does not predict into such a state: the event is sent without a prediction and the server's answer is shown. An effect-bound trigger is never predicted, and `can` for it reads only its guard's rules on the context. `start`, `send`, `retry` (which resends a start or event that failed in transport, or stayed `SERVER_OUTDATED` past every retry, under its first request id), `can`, `available`, `get`, `subscribe`, `dispose`. |
| `DEFAULT_RETRY_DELAYS` | The controller's default delays between retries of a `SERVER_OUTDATED` answer or a failed read: 250, 500, 1,000, 2,000 and 4,000 ms. Override with `retryDelays`. |
| `TRANSPORT_FAILED` | The problem code (`TRANSPORT_ERROR`) of a send or read the controller could not deliver. It is the same string as `TRANSPORT_ERROR`, the sessions' code, exported under both names. |

`useServerMachine(machine, { server, id?, startInput?, startRequestId?, startStorageKey?, newRequestId?, retryDelays? })`, from
`@traxsharp/state-machine/react`, is `ServerMachineController` as a hook. Its options, its answer and an example are under
[Driving an instance from React](/docs/statemachine/drive-a-machine-instance-from-react).
