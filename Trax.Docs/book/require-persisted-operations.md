# 17. Require persisted operations

Since chapter 12 the hub has run persisted operations in shadow mode: every document it registered
runs by id, anything sent as text runs too, and the hub logs what it would refuse. In this chapter
it refuses. The hub then runs only documents it registered when it started, and nothing a caller
writes.

This chapter starts from the end of [chapter 16](/docs/book/checkout-in-the-browser).

## What the hub registers

Every document that reaches the hub now has to be one of these, each under an id with a prefix of
its own:

| Prefix | Whose | Where from |
|---|---|---|
| `trax_client_` | the storefront's | `web/src/graphql/`, through `trax.documents.json` (chapter 15) |
| `trax_machine_` | the checkout machine's operations | generated by the hub for every machine it serves |
| `trax_progress_` | `runProgress`, its query and its subscription | generated by the hub for trains marked `[TraxRunProgress]` |
| `trax_console_` | the operations console's | shipped inside `Trax.Api.Dashboard`, registered by `UseTraxApiDashboard` |

The storefront already sends nothing else, and the console sends its documents by id whenever the
hub runs persisted operations, as it has since chapter 12. Neither changes.

The ids are what make a refusal safe. A document's id is a hash of its text, so an id names exactly
one document, and the hub checked each one against its schema and its rules when it started. A
caller can choose which registered document to run and with which variables, and nothing else.
Who may run each one is still decided by `[TraxAuthorize]` and the operations gate, as before:
persisted operations decide what can be asked, not who may ask it.

## Make the hub refuse

`Shopfront.Hub/Program.cs`:

{{csharp compile=app file=Shopfront.Hub/Program.cs}}

What changed:

- **`RequirePersisted(requirePersisted)`** is on wherever the hub runs. A document sent as text is
  refused, on HTTP and on the socket, with `PERSISTED_OPERATION_REQUIRED`.
- **`LogNonPersistedRequests`** goes with shadow mode, so it is on only when text may run.
- **`DisableIntrospection()`.** Introspection is a document written as text as well, the one a
  tool sends to read the schema, and a host that runs only its own documents has no caller who
  needs it. `trax client` reads the manifest, not the schema.
- **`PersistedOperations:Require`** can turn the refusal off, in Development only. Outside
  Development the hub ignores it, so a deployed hub cannot be configured into accepting text. It
  is there for the tests and for exploring by hand with `curl`.

## What a caller sees

Start the hub, and send the catalogue's document as text, as chapter 7 did:

```bash
curl -s -w ' %{http_code}' http://localhost:5080/trax/graphql -H 'Content-Type: application/json' \
  -d '{"query":"{ discover { products(order: { sku: ASC }) { nodes { sku name price stock } } } }"}'
```

```text
{"errors":[{"message":"Only persisted operations are accepted on this server.","extensions":{"code":"PERSISTED_OPERATION_REQUIRED"}}]} 400
```

The same document by the id the storefront's client holds runs:

```bash
CAT=$(grep -o 'trax_client_Catalogue_[a-z0-9]*' web/src/trax/documents/catalogue.g.ts)
curl -s http://localhost:5080/trax/graphql -H 'Content-Type: application/json' -d '{"id":"'$CAT'"}'
```

```text
{"data":{"discover":{"products":{"nodes":[{"sku":"CAP","name":"Cap","price":18.50,"stock":0},{"sku":"MUG","name":"Mug","price":12.00,"stock":10},{"sku":"TEE","name":"T-shirt","price":25.00,"stock":3}]}}}}
```

Introspection is refused the same way. The hub says at start which mode it is in:

```text
info: Trax.Api.GraphQL.PersistedOperations[0]
      Persisted-operation enforcement is ON. An inline query is refused unless it is allowlisted, introspection, or selects only the persisted-operations management surface. Enforcement shapes requests and is not an authorization boundary: per-type [TraxAuthorize] still decides who may run what.
```

The storefront works as it did: open it, check out and buy now. So does the console: sign in as
`lin` and it lists the runs, because each of its pages sends a document the hub registered. Its
entry page names the ids:

```text
71 documents; Executions -> trax_console_Executions_ea98447121dc28f08cf3d51a272418b4611c...
```

## What stops working

- **`curl` with a document written as text**, which every earlier chapter used. In Development,
  start the hub with `PersistedOperations__Require=false` to explore by hand again.
- **The GraphQL IDE** at `/trax/graphql` sends text and introspects. It is served in Development
  only, and refused with the rest there now.
- **A client this hub did not generate.** A mobile app, a partner's integration or a script that
  writes its own documents has to have them registered: as documents of its own, through
  `trax client --documents` like the storefront's, or uploaded through the persisted-operations
  management fields.

## What we have

The hub runs the documents it registered and nothing else: the storefront's, the ones it generates
for its machines and for following runs, and the console's. A document sent as text is refused in
every environment, unless a developer turns that off on their own machine.

The last chapter deploys Shopfront.
