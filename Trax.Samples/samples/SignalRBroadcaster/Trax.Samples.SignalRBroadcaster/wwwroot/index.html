Train events, pushed to the browser

Every train run raises lifecycle events. The SignalR sink pushes each one to every browser connected to the hub as it happens. This page never asks for them.

How it is wired
  1. The sink: which events, which trains, and what each event carries. .UseBroadcaster(b => b .UseSignalRHub(hub => hub .OnlyForEvents("Started", "Completed", "Failed") .OnlyForTrains<IPingTrain>() .WithProjection( LiveTrainEvent.From)))
  2. The hub, and who may connect to it. It will not start without saying. app.MapTraxTrainEventHub(hub => hub.RequireRoles("Operator"));
  3. This page: a plain SignalR client, listening for one message. hub.on("TrainEvent", (evt) => ...);

The hub admits signed-in operators only

It sends every train's events to every client it lets in, so it has to say who may connect. Here that is anyone signed in with the Operator role; the cookie travels with the connection by itself.

The demo sign-in exists only in Development.
